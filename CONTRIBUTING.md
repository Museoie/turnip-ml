# Contributing to turnip-ml

## Setup

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r PoseAccuracy/requirements.txt
```

CI is Python 3.12 on Ubuntu (`PoseAccuracy/requirements.txt` pins every
dependency — do not loosen pins; dependency drift must never move the
score).

## Where things live

| Path | What |
|---|---|
| `PoseAccuracy/README.md` | The pose-accuracy CI gate: metric, override policy, local run steps |
| `PoseAccuracy/FIXTURES.md` | Rebuilding the fixture set (the only supported way to add/remove clips) |
| `PoseAccuracy/requirements.txt` | Pinned Python deps |
| `.github/workflows/pose-accuracy.yml` | CI: runs on PRs touching `PoseAccuracy/**` or itself |

This file is the pointer doc; the READMEs above are the source of truth.

## Rules that are not negotiable

1. **The scorer is fully deterministic.** `PoseAccuracy/scorer.py` must
   produce byte-identical scores on re-run: sorted JSON keys, 4-decimal
   rounding on every float, no timestamps, no dict-order dependence. If
   you touch scoring, prove it by running the scorer twice on the same
   input and diffing the outputs.

2. **`baseline.json` is a locked file.** It is only regenerated by the
   full fixture rebuild (`PoseAccuracy/rebuild_fixtures.py`, see
   `PoseAccuracy/FIXTURES.md`) — never hand-edited. A baseline change is
   legitimate only when the clip set or the reference labels changed
   (the rebuild regenerates all three consistently); a score drift from a
   code or dependency change is a real regression, not a reason to move
   the baseline. Baseline changes get explicit maintainer review, and a
   merged baseline change lands with its rebuild QA notes.

3. **Trick labels come from Hoie — never inferred from footage.** Do not
   guess what trick a clip shows; the labels in
   `fixture-manifest.json` are his words.

4. **Large artifacts are never committed.** No model binaries, datasets,
   or videos in git. Fixture videos are fetched from the public R2 URLs
   and sha256-verified against the manifest on every download; the
   MoveNet model is fetched from TFHub and sha256/size-verified before it
   runs. Any helper that downloads external bytes must verify hashes and
   fail loudly on mismatch — never silently pass.

5. **No secrets, ever.** The harness runs on fork PRs, where secrets are
   invisible; fixture access is deliberately secrets-free (public URLs,
   repo *variables*). Do not add anything that needs a secret to CI.

## Pull requests

Work happens on the `Museoie/turnip-ml` fork (no push access to
`hoiekim/*`); open cross-fork PRs against `hoiekim/turnip-ml` `main`.

Use this as the PR body:

```markdown
## Summary
<what changed and why>

## Related issues
Closes hoiekim/turnip-ml#<N>

## Test plan
<what you ran: e.g. scorer unit tests, full local gate run per PoseAccuracy/README.md>

## Determinism check
<scorer touched: ran twice on identical input, outputs byte-identical — yes/no; scorer not touched: n/a>

## Checklist
- [ ] `requirements.txt` pins unchanged (or drift justified)
- [ ] No model binaries, datasets, or videos committed
- [ ] `baseline.json` untouched unless the fixture set changed
```

## CI on your PR

- The pose-accuracy gate runs the harness over the three fixture clips
  and fails on any score more than 0.5 points below `baseline.json`.
  If the regression is accepted (deliberate model change), a maintainer
  adds the `pose-accuracy-override` label and re-runs — the label only
  applies to accepted regressions, it never merges code by itself.
